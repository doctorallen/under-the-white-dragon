# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Downlevel (the repo is still named `underhill`, the game it replaced) is a side-scrolling cyberpunk game for the phone browser, held sideways, in plain JavaScript: no build step, no dependencies, no modules. You live in an apartment on floor 31 of a megablock in a vertical city, take the elevator down to the Stack, and go down level by level: strip machines for salvage, cut through grates and shutters, jack into data nodes for programs, sell to vendors, take cases from the lieutenant at the precinct, fly your spinner, get gadgets from the quartermaster and gear from the fabricator, work cases (clues, leads, the baseline test, a verdict on a suspect who may be a synth), and fight drones, chromed gangs and bosses down to the Root. Implants are illegal in this world: the detective carries gadgets, never ware. Read `README.md` for the file map and controls, `js/tuning.js` for every number, `js/items.js` for what you carry, gear, the fabricator, gadgets and programs, `js/cases.js` for the detective's cases, `js/quests.js` for jobs, and `DESIGN.md` for the design. Sections of `DESIGN.md` marked **(proposed)** aren't built yet. Ask before building on them in a way that's hard to undo.

## Commands

```sh
python3 -m http.server 8000     # play at http://localhost:8000
npm install                     # test tools only (puppeteer-core)
npm test                        # everything CI runs: test/check.sh, then test/smoke.js
```

`test/smoke.js` uses puppeteer-core with `$CHROME`. Where that isn't installed it falls back to the `playwright` package's Chromium.

## Architecture

- **Globals and load order.** Every file is a classic script in one global scope, loaded in order by `index.html` (`util.js` first, `main.js` last). A new file needs its `<script>` tag and a line in `sw.js`'s `FILES` (`test/check.sh` fails on either missing, and on duplicate top-level names).
- **Installable, never stale.** `manifest.webmanifest` and `sw.js` make it a PWA. The service worker goes to the network first for everything (revalidating past the HTTP cache) and uses its cache only offline. The deploy stamps `__BUILD__` in `sw.js` and `js/pwa.js` (`PAGE_BUILD`) with the commit and writes `version.json`, so every deploy is a new worker; `js/pwa.js` checks for one whenever the game returns to the foreground and every 15 minutes, and when it takes over, saves and reloads, unless the page is already that build (a fresh launch after a deploy loads the new code from the network, so it mustn't reload again). Don't make the worker cache-first.
- **Levels are code.** Each level in `levels.js` is built once through the builder in `world.js` (`newLevel`): painting operations (`L.paint`, `L.block`, `L.sign`, `L.tube`…), solid boxes (`L.solid`, `L.wall`, `L.floor`), one-way surfaces (`L.walk` walkways, `L.stairs`, stood on from above only), ladders, props, lights, people (`L.npc`, with a daily schedule) and enemies. `World.load(id)` makes it the current level. A save keeps only what changed: props done by id (`Game.s.done`), flags, what you carry (`pack`) and wear (`gear`, with levels), gadgets, programs, cases, jobs, rank and the time (`save.js`, localStorage `downlevel.save.v1`; save version 3, and `Save.start` moves a version 2 save's stash into the pack; old `mods` become `gadgets`).
- **Seeded.** Painting and sprites use `hash` and `Rng` only, never `Math.random` (enforced by `check.sh`), so the city always paints the same.
- **Painting.** `paint.js` paints the level lazily in chunks (`T.chunk` px square). A chunk runs only the operations whose box touches it; each operation gets its own seed (`op.seed`), so strokes meet across chunk edges without seams. Everything is laid in short strokes of close tones (`strokeRow`), and blocks are lit side-on (`blockV`: lit lips, west faces, soot undersides, drips). Behind it a level can have parallax layers (`L.layers`, back to front, each painted once and moved at its fraction `f` of the camera's speed); `skyline.js` paints their towers (`tower`, `skylineLayer`, `cloudBands`) and draws what moves on them each frame: giant holograms (`L.holos`) and the monorail train (`L.train`). A chunk is a colour canvas plus a glow canvas.
- **Rendering** (`render.js`). The view is small (`T.view.min` world px on the short side, `T.view.min × AP` art px; see Grain below) and scaled up by whole device pixels: the frame is finished at `View.out` screen pixels per view pixel (at most 3, lower when `Perf` in `main.js` sees frames under 40 a second, or as the dev setting says) and CSS scales the canvas the rest of the way, pixelated. People are lit by tinting their sprite, and the tinted copy is cached on the sprite by quantised colour (`s.lit`), so a figure costs one draw a frame; don't go back to compositing through a shared scratch canvas per figure, which stalls the GPU. Order: far layer, chunks (each erasing the far layer's glow behind it), props, then the light map (`lightMap`, a 4 px grid fixed to the world, scaled up smooth) multiplied over all of it (each light adds itself only over the cells it reaches). Keep it smooth: hard light cells read as a grid over the screen. People and enemies are lit after that, each by the light where they stand with a floor (`lightAt`), so figures always read. Then the parts of props in front of people (`p.front`) and rain. The 2D canvases stop there: `View.low` (the lit picture) and `View.gl` (what glows) go to `gl.js`, which finishes the frame in WebGL2: the glow halved by averaging and blurred into two bloom layers (averaging keeps the bloom steady as the camera moves), then picture + glow + bloom, wet reflections (`L.wet`) and the fade, scaled up to the screen. Without WebGL2, or with `?nogl` in the address, `render.js` finishes it in 2D; the smoke test plays the desktop run that way.
- **Grain.** World px are the unit for positions, physics, collision, levels and every number in `tuning.js`; art px are what's painted. `AP` (`util.js`) is art px to a world px: 1, or 3 with FINE GRAIN (`Game.s.settings.fine`, read before anything is built, reloads when switched; `?fine`/`?coarse` override; only with WebGL2). Drawing converts with `ap(v)` and always lands on whole art px: never draw a sprite or chunk at a non-integer scale, and keep every `AP === 1` path exactly as it was (normal mode must stay pixel-identical). `Pix` (`paint.js`) keeps `w`/`h`/`ox`/`oy` in world px and `W`/`H` in art px: `area` samples each art px at its world point and lays strokes per world row (`strokeRow` with `C = 8 * AP`, so strokes keep their length in the world), `put` fills an AP × AP block, `fine` sets one art px, `each` paints art px by art px (round windows, lanterns, fans; a painter that only has `put` comes out in blocks). `Spr(w, h, seed, k = AP)` rasterizes its shapes at k× with runs counted in authored px; `px` is a k × k block and `dot` one art px; `done()` gives size and anchors in art px. Chunks are 64 world px at fine (192 art px, about a normal chunk's painting time), the 160 used last kept. The camera works in art px (`View.cxA`, `View.sx/sy`), `worldGrid` draws old world-px fills on the art grid, the light map stays a 4 world px grid, the lit cache (`s.lit`) is smaller, and `gl.js` averages the glow down to world px before bloom. The world is framed the same at both grains: `View.scale` (device px per art px) is a whole number of device px to a world px over `AP`, so at fine it can be a fraction, and then the frame is made at the next whole number and the browser brings it down smoothly. The pause map paints at grain 1 (it shows a world px as a px at most).
- **Sprites** are painted from shapes (`Spr` in `spr.js`: `ell`, `box`, `cap`, `shape`, `limb`, `poly`) and cached. People come from `person(o)` in `people.js` (hair, coat, chrome, what they hold, a pose). The runner's gear and gadgets show on the sprite (`RunnerArt`). Sprites carry anchors `ax`/`ay` at the feet.
- **Play.** `player.js` moves the runner against the level and works Use (`Player.interact`: the nearest prop or person; salvage and cutting are held). Props' kinds, looks and uses are in `things.js`. People and enemies are in `actors.js`. Jacking in is `hack.js`. `life.js` is the city's ambient life: light flicker (`L.sign`/`L.tube`/`L.fire` lights carry a `flick` mode), adverts (`L.ad`), flying traffic on the far layer (`L.traffic`), critters (`L.critter`), litter (`L.litter`), smoke and steam (`L.vents`), drips (`L.drips`); it's all driven by the clock and `hash`, so none of it is saved. Passers-by come from `crowd()` in `levels.js`. `Game` (`game.js`) has the rules: what you carry (no limit, and nothing is lost on death) and payment, gear (`GEAR` in `items.js`: a piece a slot, Cyberpunk-style head, face, outer and inner torso, legs, feet, ranged and melee; armour, weapon stats and perks come from what's worn, and its `look` dresses the runner's sprite), jobs, the clock, moving between levels (`Game.go`), damage and death.
- **Cases and jobs.** `cases.js` has the cases (`CASES`, state in `Game.s.cases`): clues, leads, a suspect, a verdict; the night desk generates one from the day (`Cases.nightOffer`); `Baseline` is the test; the photo enhancer is `Enhancer` in `enhance.js` (a camera still of the scene with a few spots too small to read, one the clue's detail and the rest decoys; zoom in on one and it sharpens into its own little picture). `quests.js` has jobs (`QUESTS`, steps go/talk/collect/kill/deliver/choose/use/hack, state in `Game.s.quests`), named elites and the warrants board; `Quests.event` hears kills and uses, `Quests.tick` checks the rest. Neither puts anything in a level's code: `World.questProps` adds the clue and pickup props, and `Actors.questSpawns`/`caseNpcs` add witnesses, suspects, elites and fugitives, whenever a case or job moves on. Their panels are in `panels.js` (`PANELS`, bound by `panelBind`).
- **Places and travel.** Every place is built by hand. `kit.js` holds the pieces (buildings `bShophouse`, `bCapsules`, `bMachiya`, `bTemple`, `bPagoda`, `bGlass`, `bStack`, `bDanchi`, `bTheater`, `bBath`, `bArcade`, `bPark`; painters `kRoof`, `kLattice`, `kNoren`, `kLantern`, `kAwning`, `kBalcony`, `kWin`, `kShop`, `kTree`, `kTorii`...; stalls `kStallAt`) and `district(o)`, the frame a place is built in (ground, the city behind or a ceiling, the way in, crowd, light), with `addDistrict` to register it and `kFoes` to place enemies. The places are in `d_high.js`, `d_street.js`, `d_under.js`, `d_old.js`, `d_works.js`, `d_deep.js`; each file's own helpers carry its prefix (`hi`, `st`, `un`, `ot`, `wk`, `dp`). From the ground the camera shows about G-155 to G, so keep the detail that matters low. Every level has `metres` (its depth) and `mapX`; `worldmap.js` pins them on the city map, which is how you travel, and `Travel` (`travel.js`) decides what's open (keys and where you've been) and how you get there (spinner, manhole, subway, lift cage). The city layers behind sky places are painted once and shared (`World.shared`). Enemies are defined in `enemies.js` (`ENEMY`, AI and art in `Foes`).
- **Flying.** `flight.js`: a flight is its own mode; while `Flight.on`, `step` runs only the flight and `render` draws it (its own painted copy of `cityLayers`) before the usual finish (`finishFrame`), then `Game.arrive`.
- **Map and dev.** `map.js` paints every chunk of the level into one picture (cached per level) for the pause map; `dev.js` holds testing switches in localStorage `downlevel.dev` (god mode in `Game.hurt`, speed in `Player`, the clock in `step`).
- **Time.** `step(dt)` (`main.js`) is one fixed 1/60 s step. Panels and jacking in set `Game.paused`.

## Testing changes

`node test/smoke.js` plays through the slice headlessly on a phone and a desktop: it steps the game with `step(1/60)` and drives the controls through `Input.bot` and the edge flags (`Input.useHit`, `strikeHit`…), and writes screenshots to `test/out/` (gitignored). Look at them for visual changes. `?seed` isn't used; the levels are fixed.

## Conventions

- Comments and in-game text are plain English. Match the surrounding density.
- Commits go to `main` with short sentence-case subjects. Every push to `main` deploys to GitHub Pages once the checks pass.
