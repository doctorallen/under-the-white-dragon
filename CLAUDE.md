# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Under the White Dragon (it grew out of Downlevel, a detective game whose mechanics are gone now) is a side-scrolling cyberpunk game for the phone browser, held sideways, in plain JavaScript: no build step, no dependencies, no modules. It's a game about fixing things in a vertical city: you live in a hidden basement under the White Dragon, a noodle bar (`d_dragon.js`: the street, the bar, the storeroom and its trapdoor, and the basement `d_cellar`, where new games start; it's `hidden`, so not on the city map), take jobs to your bench (`bench.js`), use parts with a grade and a history (`parts.js`), strip machines for salvage and parts, sell to the stalls, take cabs about the city, and watch your heat (`jobs.js`); its design is in the doc linked from `DESIGN.md`. There's no fighting, no health, no gear and no detective work: the touch controls are a stick, Use and Jump, and the city's people are residents with lives (`town.js`, run by Tyrell through `city.js`). The city runs in bands from the sky down (`STRATA` in `worldmap.js`): up high, street level, the undercity, Old Town, the Works and the Bowels, each opening once you've been in the one above (`Travel.open`). Dev settings show only with `?dev`. Read `README.md` for the file map and controls, `js/tuning.js` for every number, `js/items.js` for the salvage you carry, `js/parts.js` for parts and devices, and `DESIGN.md` for the design. Sections of `DESIGN.md` marked **(proposed)** aren't built yet. Ask before building on them in a way that's hard to undo.

## Commands

```sh
git submodule update --init     # Tyrell, the minds engine, in vendor/tyrell (needed to run)
python3 -m http.server 8000     # play at http://localhost:8000
npm install                     # test tools only (puppeteer-core)
npm test                        # everything CI runs: test/check.sh, then test/smoke.js
git -C vendor/tyrell pull origin main   # take a newer Tyrell (then run the tests and commit the pointer)
```

`test/smoke.js` uses puppeteer-core with `$CHROME`. Where that isn't installed it falls back to the `playwright` package's Chromium.

## Architecture

- **Globals and load order.** Every file is a classic script in one global scope, loaded in order by `index.html` (`util.js` first, `main.js` last). A new file needs its `<script>` tag and a line in `sw.js`'s `FILES` (`test/check.sh` fails on either missing, and on duplicate top-level names).
- **Installable, never stale.** `manifest.webmanifest` and `sw.js` make it a PWA. The service worker goes to the network first for everything (revalidating past the HTTP cache) and uses its cache only offline. The deploy stamps `__BUILD__` in `sw.js` and `js/pwa.js` (`PAGE_BUILD`) with the commit and writes `version.json`, so every deploy is a new worker; `js/pwa.js` checks for one whenever the game returns to the foreground and every 15 minutes, and when it takes over, saves and reloads, unless the page is already that build (a fresh launch after a deploy loads the new code from the network, so it mustn't reload again). Don't make the worker cache-first.
- **Levels are code.** Each level (in the `d_*.js` files; what they share is in `levels.js`) is built once through the builder in `world.js` (`newLevel`): painting operations (`L.paint`, `L.block`, `L.sign`, `L.tube`…), solid boxes (`L.solid`, `L.wall`, `L.floor`), one-way surfaces (`L.walk` walkways, `L.stairs`, stood on from above only), ladders, props, lights and people (`L.npc`, with a daily schedule). `World.load(id)` makes it the current level. A save keeps only what changed: props done by id (`Game.s.done`), flags, what you carry (`pack`), the parts and notebook, the bench, jobs, heat, tips, the time, and the residents' minds (`save.js`, localStorage `whitedragon.save.v1`, save version 1; `Save.start` deletes Downlevel's old save, `downlevel.save.v1`, drops what an older save kept that nothing reads now, `Game.OLD`, and starts over from any save of another version).
- **Seeded.** Painting and sprites use `hash` and `Rng` only, never `Math.random` (enforced by `check.sh`), so the city always paints the same.
- **Painting.** `paint.js` paints the level lazily in chunks (`T.chunk` px square). A chunk runs only the operations whose box touches it; each operation gets its own seed (`op.seed`), so strokes meet across chunk edges without seams. Painting is flat (`PAINT_FLAT` in `paint.js`): each surface one tone from its value, a crisp lit top edge and shaded bottom (`blockV`), panel lines, drips, no noise and no brushwork. (Set it false and the old way comes back: short strokes of close tones, `strokeRow`, and bevelled lips.) Behind it a level can have parallax layers (`L.layers`, back to front, each painted once and moved at its fraction `f` of the camera's speed); `skyline.js` paints their towers (`tower`, `skylineLayer`, `cloudBands`) and draws what moves on them each frame: giant holograms (`L.holos`) and the monorail train (`L.train`). A chunk is a colour canvas plus a glow canvas.
- **Rendering** (`render.js`). The view is small (`T.view.min` px on the short side) and scaled up by whole device pixels: the frame is finished at `View.out` screen pixels per view pixel (at most 3, lower when `Perf` in `main.js` sees frames under 40 a second, or as the dev setting says) and CSS scales the canvas the rest of the way, pixelated. People are lit by tinting their sprite, and the tinted copy is cached on the sprite by quantised colour (`s.lit`), so a figure costs one draw a frame; don't go back to compositing through a shared scratch canvas per figure, which stalls the GPU. Order: far layer, chunks (each erasing the far layer's glow behind it), props, then the light map (`lightMap`, a 4 px grid fixed to the world, scaled up smooth) multiplied over all of it (each light adds itself only over the cells it reaches). Keep it smooth: hard light cells read as a grid over the screen. People are lit after that, each by the light where they stand with a floor (`lightAt`), so figures always read. Then the parts of props in front of people (`p.front`) and rain. Day and night are `day.js` (`Day`, numbers in `DAY`): in places open to the sky (`L.open`, from `district`'s `sky`) the light map's ambient goes toward a grey overcast by day (rose at dawn, amber at dusk), a haze goes over the city behind (and the flight's) and the neon's bloom dims; interiors and the undercity keep their own light. It's driven by the clock alone. The 2D canvases stop there: `View.low` (the lit picture) and `View.gl` (what glows) go to `gl.js`, which finishes the frame in WebGL2: the glow halved by averaging and blurred into two bloom layers (averaging keeps the bloom steady as the camera moves), then picture + glow + bloom, reflections (`L.wet`: water always; a street's, marked `rain`, only as wet as `Weather.wet()` says) and the fade, scaled up to the screen. The weather is `Weather` in `day.js` (`WEATHER`): rain comes and goes in spells worked out from the day's number, drizzle to downpour (`Weather.rain()`, which scales the rain drawn and the splashes, and puts up umbrellas), and the ground dries after; places under a roof or glass (`rain: 0`) get none. Dev can force it. Without WebGL2, or with `?nogl` in the address, `render.js` finishes it in 2D; the smoke test plays the desktop run that way.
- **Sprites** are painted from shapes (`Spr` in `spr.js`: `ell`, `box`, `cap`, `shape`, `limb`, `poly`) and cached. Every sprite is flat pixel art by default, props and figures alike (`Spr.soft` gives the old soft-run shading if something needs it): three hard tones a material and no noise, a box a flat panel (lit top and left edge, shaded bottom and right), a shadow line where a later part (`S.part()`) lies over an earlier one (`S.part(false)` for one that casts none, like hair on a face), and a dark outline, with the details (eyes, a coat's opening and buttons, a buckle, seams and rivets) placed by hand. Keep everything flat: no soft volume shading, no bevels or embossing. People come from `person(o)` in `people.js` (hair, coat, chrome, what they hold, a pose), side-on, or from behind with `view: 'back'` (`personBack`: the runner on a ladder). The runner wears their work clothes (`RUNNER` in `player.js`, drawn by `RunnerArt`). Sprites carry anchors `ax`/`ay` at the feet.
- **Play.** `player.js` moves the runner against the level and works Use (`Player.interact`: the nearest prop or person; stripping is held). Props' kinds, looks and uses are in `things.js`. People are in `actors.js`. `life.js` is the city's ambient life: light flicker (`L.sign`/`L.tube`/`L.fire` lights carry a `flick` mode), adverts (`L.ad`), flying traffic on the far layer (`L.traffic`), critters (`L.critter`), litter (`L.litter`), smoke and steam (`L.vents`), drips (`L.drips`); it's all driven by the clock and `hash`, so none of it is saved. Passers-by come from `crowd()` in `levels.js`. Nobody is only a part: anyone a builder calls "Commuter" or "Fruit seller" (`PARTS`) gets a name of their own as the level is built (`personName`, from the level and where they stand, the same every visit and unique in the city, which the smoke test checks), the part kept as their `title`. Wanderers keep to the stretch of floor they can walk (`Actors.ground`: `lane`) and go away by the nearest door or street end (`out`). `Game` (`game.js`) has the rules: what you carry (salvage, no limit) and payment, the clock, and moving between levels (`Game.go`). Stripping shows what came out a line each, rising over the machine (`Game.gain`, drawn by `Hud.tick`).
- **Places and travel.** Every place is built by hand. `kit.js` holds the pieces (buildings `bShophouse`, `bCapsules`, `bMachiya`, `bTemple`, `bPagoda`, `bGlass`, `bStack`, `bDanchi`, `bTheater`, `bBath`, `bArcade`, `bPark`; painters `kRoof`, `kLattice`, `kNoren`, `kLantern`, `kAwning`, `kBalcony`, `kWin`, `kShop`, `kTree`, `kTorii`...; stalls `kStallAt`) and `district(o)`, the frame a place is built in (ground, the city behind or a ceiling, the way in, crowd, light), with `addDistrict` to register it, and `arena` for a great hall at a street's end. The places are in `d_high.js`, `d_street.js`, `d_under.js`, `d_old.js`, `d_works.js`, `d_deep.js`; each file's own helpers carry its prefix (`hi`, `st`, `un`, `ot`, `wk`, `dp`). From the ground the camera shows about G-155 to G, so keep the detail that matters low. Build to the people's scale (an adult is 33 px): a door 40 px high, a storey about 50, a window about 18 × 22 (`KS` in `kit.js`). Every level has `metres` (its depth) and `mapX`; `worldmap.js` pins them on the city map, which is how you travel, and `Travel` (`travel.js`) decides what's open (where you've been: a band opens once you've been in the one above, `BAND_ABOVE`) and how you get there (cab, manhole, subway, lift cage). The city layers behind sky places are painted once and shared (`World.shared`).
- **The basement.** `Bench` (`bench.js`) is a panel with its own canvas (`BW` × `BH` bench pixels, drawn flat and scaled up) and a side of HTML it redraws alone (`Bench.side`); what's on the bench is saved (`Game.s.bench`), the tools' state in hand isn't. Devices and parts are data in `parts.js` (`DEVICE`, `PART`, `GRADE`, `PART_STOCK`); parts you have are instances in `Game.s.parts`, the notebook is `Game.s.notes`. `Jobs` (`jobs.js`) puts its customers into the White Dragon (`Jobs.spawn`, from `Actors.spawns`), talks through the talk panel (`Jobs.actionsFor`, `Jobs.html`), keeps heat (`Game.s.heat`) and writes the morning after when you sleep (`Jobs.morning`). Residents also bring small paid repairs, two a day (`Jobs.oddToday`, `ODD`; a scrap part fitted in one may give out overnight, and that resident stays away a few days, `sour:` flags), and tips: `Tips` (`tips.js`) sends a message in the morning or has them tell you (`TIPS`, `Game.s.tips`), and `World.tipProps` puts the machine in its level; it strips only with a good enough kit (`Game.s.tools`, `TOOLS`, `STRIP_TIER`; `TIP_YIELD` in `parts.js`).
- **The residents' minds: Tyrell.** The block's residents are run by Tyrell, a minds engine in its own repository (github.com/doctorallen/tyrell), pulled in as a git submodule at `vendor/tyrell`; `index.html` loads its built `dist/tyrell.js` (one global, `Tyrell`) before everything else, `sw.js` caches it, `check.sh` fails if it's missing, and the deploy checks out submodules and copies that one file. Its docs are in `vendor/tyrell/docs/` (start with `README.md`; `for-ai.md` is written for agents). `city.js` is the White Dragon's shell for it (`City`): it declares the needs (hunger, energy, fun, company), the places (every `TOWN_PLACE`, each flat as `flat:<letter>`, street spots as `street@<x>`, the ends of the city as `away:<side>@<street>`, each with its level as its region), the actions, and every resident, whose day (`Town.plans`, as `Town.init` spaced it) becomes their routine (work holds at rank 2; time at home is `*`, anything they like there). Travel times come from `Town.route` at the residents' pace (`PXH`), so arrivals agree on screen and off. Tyrell decides where everyone is; `City.state(id)` turns that into `Town.state`'s shape (a route walked by progress, or a spot by activity via `Town.point`), and `Town.state` uses it whenever `City.on`. The game's clock drives Tyrell's (`City.sync`, from `Town.sync`: minutes = (day × 24 + time) × 60), forward and, through Esper's time walk, back (further back than it remembers, the block starts over). The player is a person to them: talking to someone (`City.did('talked')`), a repair (`fixed`, `botched` from `Jobs`) go in their file on you; stripping someone's machine in front of residents is sensed (`City.strip`, from `things.js`), they believe it, gossip it, and may report it (heat, `CITY.reportHeat`); `City.remark` gives their lines about it, `City.morning` what's going round. Their minds are saved in `Game.s.city` (`City.stash` from `Save.write`; `City.init` after `Save.start`). The dev drawer has time walk buttons, each resident's mind (`City.inspect`, Tyrell's Palantír), and Go to someone.
- **The block and its people.** The White Dragon's street (`d_dragon`) has doors (`door` props) into hidden interiors, and each interior has its way out drawn on its back wall where you come in, often mid-room (`innerDoor` in `props.js`, `look` noren/glass/steel; `TOWN_PLACE.inside` matches it): the noodle bar (`d_noodles`, in `d_dragon.js`), Mo's grocery and the flats (`d_block.js`). Neon Row's places are in `d_neon.js` (`NR_DOORS`, `nrRoom`; the izakaya, the pet shop, the pachinko hall, the cinema, the Coil with its hours, the shrine), and the businesses' machines in them (tills, dryers, a jukebox, pachinko machines, a cash machine...) strip for heat (`OWNED` in `things.js`, `OWNED_YIELD` in `parts.js`; more if anyone's watching). Residents walk between streets too (`TOWN_PLACE` entries with a `street`, `away:<side>@<street>`, `TOWN_GAP` hours off screen between streets), and the Row's staff are residents with shifts. Walking off the end of any district takes you to the next one at the same depth (`Travel.neighbours`, `Travel.edge`; spawns `west`/`east`); spinner pads are cab stands (a fare, free once Ozzy owes you). The residents (`RESIDENTS` in `town.js`) each have a home, a job, friends and a day plan; `Town.init` expands errands and spaces the plan, `Town.state(id, hour)` gives where someone is from the clock alone (a route out of one door, along the street, in another, up the stairs), `Town.sync` keeps the ones in your level among `Actors.npcs` (`def.town`, moved by Town, not by `sched`), and `Town.chatter`/`arrived`/`talk` do greetings, small talk, the till and what they tell you. Without Tyrell, `Town.clockState` places people from the clock alone and nothing about them is saved; with it, they're Tyrell's (above).
- **Flying.** `flight.js`: a flight is its own mode; while `Flight.on`, `step` runs only the flight and `render` draws it (its own painted copy of `cityLayers`) before the usual finish (`finishFrame`), then `Game.arrive`.
- **Map and dev.** `map.js` paints every chunk of the level into one picture (cached per level) for the pause map; `dev.js` holds testing switches in localStorage `downlevel.dev` (speed in `Player`, the clock in `step`, the weather in `Weather`), Go to a place (by band, each street with its rooms: `Dev.goHtml`) and to someone (`Dev.peopleHtml`, landing beside them through `Dev.landAt` in `Game.arrive`).
- **Time.** `step(dt)` (`main.js`) is one fixed 1/60 s step. Panels set `Game.paused`.

## The look of the menus

Menus and the HUD are a game's, not a web page's: Dragon Pixel (`fonts/dragon.woff`, our own font, built by `python3 tools/mkfont.py fonts/dragon.woff` from the glyphs in that script; add a glyph there if text needs one) at 15px for text and 20px for titles and buttons; windows and cards with cut corners (`--cut`, `--cut-s` in `css/style.css`) over the dimmed game; chunky buttons (`.go` the main one). The skin is the last section of `css/style.css`. Anything a job needs is shown as a checklist with the part's picture (`Jobs.needs`, `Parts.icon`, `Parts.sources`).

## Testing changes

`node test/smoke.js` plays through the slice headlessly on a phone and a desktop: it steps the game with `step(1/60)` and drives the controls through `Input.bot` and the edge flags (`Input.useHit`, `jumpHit`), and writes screenshots to `test/out/` (gitignored). Look at them for visual changes. `?seed` isn't used; the levels are fixed.

## Conventions

- Comments and in-game text are plain English. Match the surrounding density.
- Commits go to `main` with short sentence-case subjects. Every push to `main` deploys to GitHub Pages once the checks pass.
